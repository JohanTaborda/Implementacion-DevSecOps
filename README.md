<h1 align="center">Estrategia de Branching</h1>

## Estrategia seleccionada: GitFlow

### 1. Frecuencia de despliegue esperada

El proyecto no publica cambios constantemente, sino que realiza lanzamientos planificados cada semana o cada 2 semanas. Por eso, **GitFlow se adapta bien**, ya que permite preparar y revisar una versión antes de publicarla mientras el equipo continúa trabajando en nuevas funciones. En cambio, otras estrategias están más pensadas para proyectos que realizan publicaciones varias veces al día, algo que no necesitamos actualmente.

### 2. Tamaño del equipo

El equipo está formado por 3 desarrolladores que pueden trabajar en diferentes funcionalidades al mismo tiempo. **GitFlow permite que cada desarrollador trabaje de forma independiente, evitando que los cambios de una persona interfieran con los de los demás. Además, los cambios pueden revisarse antes de integrarlos, ayudando a mantener el código organizado y reducir errores.**
